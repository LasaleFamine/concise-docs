# Concise documentation

## Assess scope and reading paths

An assessment authorizes findings and proposed changes. Edit only when the request authorizes a rewrite, and keep it within the agreed scope. Follow repository instructions and mandatory reads during assessment. State assumptions that affect which sources or tasks you sample.

Inspect entry instructions, headings, and references first. Choose representative tasks and trace how a reader reaches the required rules, facts, and commands. Search for terms and read relevant sections. Links do not load their targets into context. Follow a link when the task needs its target; do not read the whole link graph.

Classify overlapping material by role: current rules or state, procedure, evidence or history, and generated view. Identify the authoritative source and flag conflicts. Check the source before relying on a summary. Resolve authority before removing a competing statement.

## Simplify authorized material

- Give each current rule or fact one authoritative home. Replace duplicate explanations with direct, descriptive links to the relevant section. Say when to read it. Avoid chains of small pages that only point elsewhere.
- Keep constraints beside the step where a reader must act on them. A brief that must work offline or outside the repository needs the essential rules and facts in place. Name their source so the brief does not become a competing authority.
- Update summaries that describe current state and regenerate derived views from their sources. Preserve unique evidence, dates, approval scope, and historical decisions. Keep local locks, ownership rules, and intervening user edits intact.
- Use short, active sentences, consistent terms, factual headings, and one action per step. Keep exact identifiers, units, and qualifications. This is STE-inspired clarity; claim neither formal ASD-STE100 compliance nor a percentage score.

## Check retrieval and report

Verify changed links and anchors. Repeat the sampled tasks and confirm that a reader still finds the correct source, required constraints, facts, and commands. Record where a path still fails or depends on an assumption.

For a before-and-after comparison, use the same tasks and scope. Count unique content loaded per task in words, bytes, or tokens from a named tokenizer. Report the unit, link hops, and whether retrieval was correct. Separate total document size from task reading cost. Label estimates and avoid arbitrary budgets or unsupported token savings. Report the change and remaining gaps briefly.

When adding guidance, check for an existing home first. Update that source and add a task-specific link where readers look for it.
